# Process map

Auto-generated overview of every process in this workflow and the handoffs between them. The canonical source is each `<process>-states.json`; this map is regenerated from those.

## How to read it

Nodes are processes; edges are cross-process handoffs. Edge styling:

- **`==>` (thick solid)** — *shared* handoff: the same work item continues on the destination process's state machine. Both processes declare the shared resting state.
- **`-.->` (dashed)** — *spawn*: a new work item is created on the destination process. The originating issue and the spawned issue are tracked independently.

Edge labels name the state involved in the handoff — the shared resting state for shared handoffs, or the destination state for spawn events.

## What this map does NOT show

- **Editorial groupings** (Build / Ship / Respond / Learn lanes). The auto-generated map has no concept of phase — add a `phase` field to each state machine JSON if you want lanes.
- **Edge tiers** (primary happy path vs feedback vs conditional). The auto-generated map distinguishes only shared vs spawn.
- **Rolled-up labels** like `ready_for_dev / exp / spike` — each shared state appears as its own edge.
